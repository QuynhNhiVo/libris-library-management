1. Giới thiệu INTRODUCTION

1.1 Mục đích tài liệu

Tài liệu Đặc tả Yêu cầu Phần mềm (SRS) này mô tả đầy đủ các yêu cầu chức năng và phi chức năng của hệ thống Libris — Ứng dụng Quản lý Thư viện Desktop. Tài liệu được tạo tự động từ phân tích mã nguồn thực tế của dự án, bao gồm các package: model, dao, controller, ui, utils, config, và helpers.

Đối tượng đọc: nhóm phát triển, giảng viên, người đánh giá dự án và các bên liên quan khác cần hiểu rõ chức năng, kiến trúc và hành vi của hệ thống.

1.2 Phạm vi hệ thống

Libris là ứng dụng desktop (Java Swing) dùng để quản lý hoạt động cho thuê sách tại thư viện. Hệ thống hỗ trợ hai vai trò người dùng chính:

👨‍💼
Admin (Quản trị viên)
  • Quản lý danh mục sách (CRUD)
  • Quản lý khách hàng (CRUD)
  • Quản lý đơn thuê sách
  • Duyệt / Từ chối đơn thuê
  • Xem Dashboard tổng quan
  • Xem báo cáo & thống kê
  • Xuất dữ liệu ra Excel
👤
Customer (Khách hàng)
  • Xem danh sách sách có sẵn
  • Tạo yêu cầu thuê sách
  • Xem danh sách sách đang thuê
  • Yêu cầu trả sách
  • Quản lý hồ sơ cá nhân
  • Đổi mật khẩu

2.4 Đối tượng sử dụng & Vai trò

Vai tròMô tảSidebar Menu
Admin Quản trị viên thư viện — toàn quyền quản lý sách, khách hàng, đơn thuê và xem báo cáo. Tài khoản Admin không liên kết với bảng Customers (CustomerID = NULL). Tổng quan · Quản lý sách · Khách hàng · Đơn thuê · Báo cáo

2.5 Ràng buộc hệ thống

  • Hệ thống chạy dưới dạng ứng dụng Desktop standalone (Java Swing), không có server riêng.
  • Cơ sở dữ liệu SQLite lưu tại file Libris.db cùng thư mục với ứng dụng.
  • Kết nối database dùng chế độ WAL (Write-Ahead Logging) với busy_timeout=30000ms.
  • Entry point của ứng dụng: com.libris.ui.LoginView.main().
  • Kích thước cửa sổ tối thiểu: 1024 × 800 pixels.
  • Icon được load từ URL internet (unpkg.com) hoặc file local resources.

FR-01: Đăng nhập hệ thống
Mã chức năngFR-01
Tên chức năngĐăng nhập hệ thống (Login)
Vai tròAdmin Customer
Lớp liên quanLoginView → AuthController → UserDAO.login()
Mô tảNgười dùng nhập tên đăng nhập và mật khẩu để truy cập hệ thống. Hệ thống xác thực thông tin từ bảng Users (LEFT JOIN Customers để lấy thông tin profile).
Dữ liệu đầu vàoUsername (text), Password (text)
Dữ liệu đầu raĐối tượng User chứa: userId, username, password, role, customerId, fullName, email, phone
Xử lý bất đồng bộCó — sử dụng SwingWorker để tránh block UI thread

Luồng xử lý:

  1. Người dùng mở ứng dụng → hiển thị LoginView (cửa sổ 900×550).
  2. Nhập Username và Password vào form.
  3. Nhấn nút "Đăng nhập" hoặc phím Enter.
  4. Hệ thống kiểm tra: nếu username hoặc password rỗng → hiển thị thông báo lỗi "Vui lòng nhập đủ thông tin!".
  5. Nút Login chuyển sang trạng thái disabled, text đổi thành "Đang kết nối...".
  6. SwingWorker thực thi AuthController.login() trên background thread.
  7. UserDAO.login() thực hiện truy vấn SQL: SELECT u.*, c.FullName, c.Email, c.Phone FROM Users u LEFT JOIN Customers c ON u.CustomerID = c.CustomerID WHERE u.Username = ? AND u.Password = ?
  8. Nếu tìm thấy user → tạo MainFrame(user) → đóng LoginView.
  9. Nếu không tìm thấy → hiển thị "Sai tên đăng nhập hoặc mật khẩu!" → enable lại nút Login.
  10. Nếu có lỗi kết nối database → hiển thị "Lỗi kết nối cơ sở dữ liệu!".

Điều hướng sau đăng nhập:

  • Admin → trang mặc định: dashboard (Tổng quan)
  • Customer → trang mặc định: rent (Thuê sách)

FR-03: Quản lý sách
Mã chức năngFR-03
Vai tròAdmin
Lớp liên quanBooksView → BookController → BookDAO
Mô tảAdmin thực hiện CRUD trên danh mục sách: xem danh sách, thêm, sửa, xóa và tìm kiếm sách.

FR-03.1: Xem danh sách sách

  • Hiển thị bảng với các cột: Mã sách, Tên sách, Tác giả, Thể loại, NXB, Năm XB, Trạng thái, Giá thuê, Tiền cọc.
  • Sắp xếp mặc định theo BookID DESC (sách mới nhất lên đầu).
  • Dữ liệu tự động refresh khi chuyển đến trang sách.

FR-03.2: Thêm sách mới

  • Mở dialog nhập thông tin: BookCode, Title, Author, Category, Publisher, PublishYear, BookStatus, RentalPrice, DepositPrice.
  • SQL: INSERT INTO Books (...) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)

FR-03.3: Cập nhật sách

  • Chọn sách từ bảng → mở dialog sửa thông tin.
  • SQL: UPDATE Books SET ... WHERE BookID = ?

FR-03.4: Xóa sách

  • Chọn sách → xác nhận xóa → xóa khỏi database.
  • SQL: DELETE FROM Books WHERE BookID = ?

FR-03.5: Tìm kiếm sách

  • Tìm kiếm theo từ khóa, so khớp với: Title, Author, BookCode.
  • SQL: SELECT * FROM Books WHERE Title LIKE ? OR Author LIKE ? OR BookCode LIKE ?
  • Sử dụng pattern %keyword% cho tìm kiếm gần đúng.

Vai tròAdmin

Mô tảAdmin thực hiện CRUD trên danh sách khách hàng: xem, thêm, sửa, xóa và tìm kiếm.

FR-04.1: Xem danh sách khách hàng

  • Hiển thị bảng: Mã KH, Họ tên, SĐT, Email, Địa chỉ.
  • Sắp xếp theo CustomerID DESC.

  • Nhập: CustomerCode, FullName, Phone, Address, Email.
  • SQL: INSERT INTO Customers (...) VALUES (?, ?, ?, ?, ?)

FR-04.3: Cập nhật khách hàng

  • SQL: UPDATE Customers SET ... WHERE CustomerID = ?

FR-04.4: Xóa khách hàng

  • SQL: DELETE FROM Customers WHERE CustomerID = ?

FR-04.5: Tìm kiếm khách hàng

  • Tìm theo CustomerID (nếu input là số) hoặc FullName (tìm gần đúng).
  • SQL: SELECT * FROM Customers WHERE CustomerID = ? OR FullName LIKE ?
📋
FR-05: Quản lý đơn thuê sách
Mã chức năngFR-05
Vai tròAdmin
Lớp liên quanOrdersView → RentalOrderController → RentalOrderDAO
Mô tảAdmin quản lý toàn bộ đơn thuê: xem danh sách, tạo đơn mới, xem chi tiết, duyệt/từ chối đơn, xử lý trả sách.

FR-05.1: Xem danh sách đơn thuê

  • Hiển thị: Mã đơn, Mã KH, Khách hàng, Ngày thuê, Hạn trả, Trạng thái, Tiền cọc, Phí thuê, Phí phạt, Tổng tiền.
  • Sắp xếp theo OrderID DESC.
  • JOIN bảng Customers để lấy CustomerCode và CustomerName.

FR-05.2: Tạo đơn thuê mới

  • Chọn khách hàng, chọn sách (nhiều cuốn), nhập ngày thuê, hạn trả, phí.
  • Xử lý transaction: INSERT RentalOrders → INSERT RentalOrderDetails → UPDATE Books.BookStatus = 'Rented'.
  • Nếu một bước thất bại → ROLLBACK toàn bộ.

FR-05.3: Xem chi tiết đơn

  • Hiển thị thông tin đơn + danh sách sách trong đơn (BookCode, Title, Author, Category, Publisher, PublishYear, BookStatus, RentalPrice, DepositPrice).

FR-05.4: Cập nhật trạng thái đơn

  • Duyệt đơn: Pending → Renting
  • Từ chối đơn: Pending → Rejected
  • Trả sách: Renting → Returned (cập nhật ReturnDate + đổi BookStatus → 'Available')
⚠️
Transaction: Thao tác tạo đơn và cập nhật trạng thái đều sử dụng transaction (conn.setAutoCommit(false)) để đảm bảo tính toàn vẹn dữ liệu. Nếu có lỗi, hệ thống sẽ ROLLBACK và ném lại SQLException.
📖
FR-06: Thuê sách (Customer)
Mã chức năngFR-06
Vai tròCustomer
Lớp liên quanRentView → RentController → RentDAO
Mô tảKhách hàng xem danh sách sách có sẵn (status = 'Available'), chọn sách và tạo yêu cầu thuê.

FR-06.1: Xem sách có sẵn

  • Hiển thị danh sách sách có BookStatus = 'Available'.
  • SQL: SELECT * FROM Books WHERE BookStatus = 'Available'

FR-06.2: Tạo yêu cầu thuê

  • Khách hàng chọn một hoặc nhiều sách, chọn ngày dự kiến trả.
  • Hệ thống tạo đơn thuê với trạng thái Pending.
  • Mã đơn tự động: "REQ" + System.currentTimeMillis().
  • Giá thuê mặc định: 10,000 VNĐ × số sách.
  • Hệ thống tự động chuyển trạng thái sách sang Rented.
📕
FR-07: Sách đang thuê (My Rentals)
Mã chức năngFR-07
Vai tròCustomer
Lớp liên quanMyRentalsView → RentController → RentDAO
Mô tảKhách hàng xem danh sách các đơn thuê của mình (trạng thái Pending hoặc Renting) và có thể yêu cầu trả sách.

FR-07.1: Xem đơn thuê cá nhân

  • Hiển thị đơn thuê của khách hàng đang đăng nhập.
  • Lọc: CustomerID = ? AND OrderStatus IN ('Pending', 'Renting').
  • Sắp xếp theo ngày thuê giảm dần.
  • Mỗi đơn hiển thị kèm danh sách sách chi tiết (JOIN RentalOrderDetails + Books).

FR-07.2: Trả sách

  • Khách hàng chọn đơn thuê → nhấn nút "Trả sách".
  • Hệ thống cập nhật: OrderStatus = 'Returned', ReturnDate = NOW().
  • Đồng thời chuyển các sách trong đơn về trạng thái Available.
📈
FR-08: Báo cáo & Thống kê
Mã chức năngFR-08
Vai tròAdmin
Lớp liên quanReportsView → ReportController → ReportDAO
Mô tảAdmin xem các báo cáo thống kê chi tiết về hoạt động thư viện.

FR-08.1: Thống kê tổng quan (Dashboard Stats)

  • Tổng số sách, tổng khách hàng, đơn đang thuê, đơn đã trả, doanh thu tháng hiện tại.
  • Truy vấn đơn dùng subquery tổng hợp trên nhiều bảng.

FR-08.2: Doanh thu theo tháng

  • Hiển thị doanh thu 12 tháng trong năm được chọn.
  • Chỉ tính đơn có OrderStatus = 'Returned'.
  • Biểu đồ đường (Line Chart) được render bởi ChartGenerator.createRevenueChart().
  • Có thể xuất báo cáo doanh thu ra file Excel.

FR-08.3: Top sách được thuê nhiều nhất

  • Đếm số lần mỗi sách xuất hiện trong RentalOrderDetails.
  • SQL: SELECT b.Title, COUNT(od.BookID) as rentCount FROM RentalOrderDetails od JOIN Books b ON od.BookID = b.BookID GROUP BY od.BookID ORDER BY rentCount DESC LIMIT ?

FR-08.4: Thống kê theo thể loại

  • Đếm số lượt thuê theo Category của sách.
  • Sắp xếp theo số lượt thuê giảm dần.

FR-08.5: Top khách hàng thuê nhiều nhất

  • Đếm số đơn thuê theo từng khách hàng.
  • SQL: JOIN RentalOrders + Customers, GROUP BY CustomerID.

FR-08.6: Sách quá hạn

  • Danh sách đơn thuê có trạng thái Renting và ExpectedReturnDate < datetime('now').
  • Hiển thị: Mã đơn, Khách hàng, Ngày thuê, Hạn trả, Tổng tiền.
👤
FR-09: Quản lý hồ sơ người dùng
Mã chức năngFR-09
Vai tròCustomer
Lớp liên quanProfileView → AuthController → UserDAO
Mô tảKhách hàng xem và cập nhật thông tin cá nhân, đổi mật khẩu.

FR-09.1: Xem thông tin cá nhân

  • Hiển thị: Username, FullName, Email, Phone, Role.
  • Dữ liệu lấy từ UserDAO.getUserById() (JOIN Users + Customers).

FR-09.2: Cập nhật thông tin profile

  • Cho phép sửa: FullName, Email, Phone.
  • Xử lý transaction: Lấy CustomerID từ Users → UPDATE Customers.
  • Chỉ cập nhật nếu tài khoản có liên kết CustomerID (không áp dụng cho Admin).

FR-09.3: Đổi mật khẩu

  • Nhập: mật khẩu hiện tại, mật khẩu mới.
  • Kiểm tra mật khẩu hiện tại khớp → cập nhật mật khẩu mới.
  • SQL: UPDATE Users SET Password = ? WHERE UserID = ?
🔴
Lưu ý bảo mật: Mật khẩu hiện tại được lưu dưới dạng plain text trong database. Trong môi trường production, cần mã hóa mật khẩu bằng thuật toán hash (BCrypt, PBKDF2, Argon2).
📥

5. Yêu cầu phi chức năng NON-FUNCTIONAL

⚡
Hiệu năng
  • Giao diện sử dụng SwingWorker cho thao tác nặng (đăng nhập) để không block EDT.
  • SQLite WAL mode cho phép đọc/ghi đồng thời.
  • Busy timeout: 30,000ms để xử lý database lock.
  • Dữ liệu tự động refresh khi chuyển trang (navigateTo).
🔒
Bảo mật
  • Xác thực bằng Username/Password.
  • Phân quyền theo Role: Admin / Customer.
  • Sidebar menu khác nhau cho từng vai trò.
  • Cần cải thiện Mật khẩu lưu plain text.
  • Foreign Keys được bật: PRAGMA foreign_keys=ON.
🎨
Giao diện
  • Sử dụng FlatLaf Look & Feel hiện đại.
  • Bảng màu chủ đạo: Blue (#2563EB), nền sáng (#F1F5F9).
  • Font chính: Segoe UI.
  • Kích thước cửa sổ tối thiểu: 1024×800.
  • Icon SVG được load từ URL (unpkg.com) với fallback local.
  • Sidebar trái cố định, content chính dùng CardLayout.
  • Bo góc (rounded corners) trên cards và bảng.
  • Hover effects trên các nút navigation.
🗄️
Dữ liệu & Toàn vẹn
  • SQLite file-based: Libris.db.
  • Tự động khởi tạo database từ database.sql khi lần đầu chạy.
  • Transaction cho các thao tác phức hợp (tạo đơn, cập nhật trạng thái).
  • CHECK constraint trên BookStatus và OrderStatus.
  • UNIQUE constraint trên BookCode, CustomerCode, OrderCode, Username.
  • Foreign key giữa RentalOrders → Customers, RentalOrderDetails → (RentalOrders, Books), Users → Customers.
📦
Triển khai
  • Build thành JAR đóng gói (jar-with-dependencies) bằng Maven Assembly Plugin.
  • Entry point: com.libris.ui.LoginView.
  • File batch khởi chạy: run.bat.
  • Yêu cầu JRE 25+.
🔌
Khả năng mở rộng
  • Kiến trúc MVC tách biệt rõ ràng View / Controller / DAO.
  • Hệ thống icon quản lý qua Properties file → dễ thay đổi.
  • Model POJO đơn giản → dễ serialize/deserialize.
  • Config tập trung trong Constants.java.

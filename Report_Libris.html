CHƯƠNG 1: TỔNG QUAN ĐỒ ÁN

1.1. Giới thiệu đề tài

Lý do chọn đề tài quản lý thư viện (Libris):

Trong bối cảnh công nghệ thông tin phát triển mạnh mẽ, việc ứng dụng công nghệ vào quản lý thư viện là một nhu cầu thiết yếu. Hệ thống quản lý thư viện Libris được xây dựng nhằm giải quyết các vấn đề:

  • Quản lý kho sách hiệu quả: Theo dõi trạng thái sách (Available/Rented/Pending), quản lý thông tin chi tiết (mã sách, tên, tác giả, thể loại, NXB, năm XB, giá thuê, tiền cọc).
  • Quản lý người mượn: Lưu trữ thông tin khách hàng (mã KH, họ tên, SĐT, email, địa chỉ), theo dõi lịch sử mượn sách.
  • Quản lý giao dịch mượn/trả: Theo dõi quy trình mượn/trả sách từ khi tạo đơn → duyệt → trả, tính phí thuê, tiền cọc, phạt trễ hạn.
  • Báo cáo thống kê: Cung cấp Dashboard tổng quan, biểu đồ doanh thu, top sách được thuê nhiều, xuất Excel.

1.2. Mục tiêu đồ án

  • Mục tiêu chính: Xây dựng ứng dụng Desktop quản lý thư viện sách với các chức năng cốt lõi, sử dụng Java Swing.
  • Chức năng cụ thể:
    • Quản lý sách (thêm, sửa, xóa, tìm kiếm, lọc theo thể loại)
    • Quản lý khách hàng (thêm, sửa, xóa, tìm kiếm)
    • Quản lý đơn thuê sách (tạo đơn, duyệt, từ chối, trả sách)
    • Phân quyền Admin và Customer
    • Dashboard thống kê và báo cáo
    • Xuất báo cáo Excel (sách, khách hàng, đơn thuê, doanh thu)
    • Quản lý hồ sơ cá nhân và đổi mật khẩu
  • Mục tiêu học thuật: Vận dụng kiến thức Java Swing, SQLite, thiết kế giao diện Desktop, mô hình kiến trúc 3 lớp.

1.3. Phạm vi đồ án

Các chức năng chính được triển khai:

  • Đăng nhập: Xác thực người dùng, phân quyền Admin/Customer. Sử dụng SwingWorker xử lý bất đồng bộ.
  • Quản lý sách: CRUD sách, tìm kiếm theo tên/tác giả/mã sách, hỗ trợ lọc theo thể loại.
  • Quản lý khách hàng: CRUD khách hàng, tìm kiếm theo ID/tên.
  • Đặt/Thuê sách: Customer chọn sách Available, chọn ngày trả, tạo đơn thuê.
  • Duyệt đơn thuê: Admin xem và duyệt/từ chối đơn hàng Pending.
  • Trả sách: Customer trả sách, cập nhật trạng thái đơn và sách (Transaction).
  • Dashboard: 4 thẻ thống kê + đơn thuê gần đây + top sách được thuê.
  • Thống kê báo cáo: Doanh thu theo tháng (biểu đồ), top sách/KH, thống kê thể loại, sách quá hạn.
  • Xuất Excel: 4 loại (sách, khách hàng, đơn thuê, doanh thu).
  • Quản lý cá nhân: Xem/cập nhật hồ sơ, đổi mật khẩu.

CHƯƠNG 2: CÔNG NGHỆ VÀ CÔNG CỤ SỬ DỤNG

2.1. Ngôn ngữ lập trình

  • Java (Java SE / Java Swing): Sử dụng Java 25 (maven.compiler.source/target = 25).
  • Java Swing: Thư viện GUI mạnh mẽ cho ứng dụng Desktop, kết hợp FlatLaf cho giao diện hiện đại.

2.2. Cơ sở dữ liệu

  • SQLite (Libris.db): Cơ sở dữ liệu nhẹ, nhúng, không cần server.
  • Sử dụng WAL mode (Write-Ahead Logging) cho hiệu suất tốt hơn.
  • Cấu trúc gồm 5 bảng chính: Users, Customers, Books, RentalOrders, RentalOrderDetails.
  • Tự động khởi tạo database từ file database.sql trong resources nếu chưa tồn tại.

Hình 3.1: Sơ đồ chức năng hệ thống Libris

Phân quyền Admin (Quản trị viên)

  • Dashboard: Xem thống kê tổng quan (tổng sách, sách có sẵn, đang thuê, tổng KH), đơn gần đây, top sách.
  • Quản lý sách: Thêm, sửa, xóa, tìm kiếm sách.
  • Quản lý khách hàng: Xem, tìm kiếm, thêm, sửa, xóa khách hàng.
  • Duyệt đơn thuê: Xem tất cả đơn, chi tiết sách trong đơn, duyệt/từ chối đơn Pending.
  • Báo cáo: Biểu đồ doanh thu theo tháng, top sách/KH, thống kê thể loại, sách quá hạn, xuất Excel.

Phân quyền Customer (Khách hàng)

  • Thuê sách: Xem sách Available, chọn sách, chọn ngày trả, tạo đơn thuê.
  • Xem sách đang thuê: Xem danh sách đơn Pending/Renting với chi tiết sách (MyRentalsView).
  • Trả sách: Chọn đơn Renting và trả sách.
  • Hồ sơ cá nhân: Xem, cập nhật thông tin, đổi mật khẩu.

5.2. Đánh giá ưu nhược điểm của ứng dụng

Ưu điểm

  • Giao diện thân thiện, hiện đại (FlatLaf 3.7.1): Giao diện đẹp, dễ sử dụng, font Segoe UI nhất quán, phối màu xanh chuyên nghiệp (#2563EB).
  • Xử lý luồng ngầm (SwingWorker): Ứng dụng không bị đơ khi thực hiện login và các thao tác DB nặng.
  • Mô hình 3 lớp rõ ràng: Model → DAO → Controller → UI, dễ dàng bảo trì và mở rộng.
  • Phân quyền chặt chẽ: Admin và Customer có giao diện và chức năng riêng biệt hoàn toàn.
  • Transaction an toàn: Các thao tác quan trọng (tạo đơn, trả sách) sử dụng Transaction với rollback.
  • Database tự khởi tạo: Tự động tạo bảng và dữ liệu mẫu từ file database.sql nếu chưa tồn tại.
  • SQLite WAL mode: Hiệu suất đọc/ghi tốt hơn, hỗ trợ đọc đồng thời.
  • Xuất Excel chuyên nghiệp: 4 loại báo cáo với header styling, auto-size columns.
  • Biểu đồ trực quan: JFreeChart cho biểu đồ doanh thu theo tháng.
  • Lazy loading: Dữ liệu chỉ load khi truy cập trang lần đầu (loadedPages Set).

Nhược điểm

  • Mật khẩu plaintext: Mật khẩu lưu trực tiếp trong DB, chưa mã hóa (bcrypt/SHA-256).
  • Ứng dụng Desktop: Chưa triển khai Web/Cloud, hạn chế truy cập từ xa.
  • SQLite đơn giản: Không hỗ trợ đồng thời nhiều người dùng trên mạng.
  • Chưa có đăng ký tài khoản: Tài khoản được tạo thủ công trong DB.
  • Chưa có thông báo tự động: Không gửi email nhắc nhở trả sách.
  • Chưa có tính năng thanh toán trực tuyến.

5.3. Hướng phát triển trong tương lai

  • Mã hóa mật khẩu: Sử dụng bcrypt hoặc SHA-256 để mã hóa password.
  • Chuyển đổi lên Web/Cloud: Xây dựng ứng dụng web bằng Java Spring Boot + React/Vue.
  • Nâng cấp cơ sở dữ liệu: Chuyển từ SQLite sang MySQL hoặc PostgreSQL.
  • Tích hợp thanh toán trực tuyến: Thêm chức năng thanh toán online (VNPay, MoMo).
  • Tính năng đa ngôn ngữ: Hỗ trợ tiếng Anh và các ngôn ngữ khác (i18n).
  • Thông báo tự động: Gửi email nhắc nhở trả sách quá hạn.
  • Chức năng đăng ký tài khoản: Cho phép người dùng tự đăng ký.
  • Tìm kiếm nâng cao: Full-text search, lọc theo nhiều tiêu chí kết hợp.
  • Phân trang nâng cao: Phân trang phía server (offset/limit) cho dữ liệu lớn.

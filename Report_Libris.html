CHƯƠNG 1: TỔNG QUAN ĐỒ ÁN

1.1. Giới thiệu đề tài

Lý do chọn đề tài quản lý thư viện (Libris):

Trong bối cảnh công nghệ thông tin phát triển mạnh mẽ, việc ứng dụng công nghệ vào quản lý thư viện là một nhu cầu thiết yếu. Hệ thống quản lý thư viện Libris được xây dựng nhằm giải quyết các vấn đề:

  • Quản lý kho sách hiệu quả: Theo dõi trạng thái sách (Available/Rented/Pending), quản lý thông tin đầy đủ bao gồm mã sách, tên, tác giả, thể loại, NXB, năm XB, giá thuê và tiền cọc.
  • Quản lý người mượn: Lưu trữ thông tin khách hàng (mã KH, họ tên, SĐT, email, địa chỉ), liên kết với tài khoản đăng nhập.
  • Quản lý giao dịch mượn/trả: Theo dõi quy trình mượn/trả sách qua các trạng thái: Pending → Renting → Returned, tính toán phí thuê và phí trễ hạn.
  • Báo cáo thống kê: Cung cấp Dashboard tổng quan, doanh thu hàng tháng, sách phổ biến, thống kê theo thể loại, khách hàng tích cực nhất, và xuất Excel.

1.2. Mục tiêu đồ án

  • Mục tiêu chính: Xây dựng ứng dụng Desktop quản lý thư viện sách với các chức năng cốt lõi, giao diện hiện đại.
  • Chức năng cụ thể:
    • Đăng nhập và phân quyền Admin/Customer
    • Quản lý sách (thêm, sửa, xóa, tìm kiếm, lọc theo thể loại)
    • Quản lý khách hàng (thêm, sửa, xóa, tìm kiếm)
    • Quản lý đơn thuê sách (tạo, duyệt, từ chối, trả sách)
    • Dashboard tổng quan và báo cáo thống kê
    • Xuất báo cáo Excel
    • Quản lý hồ sơ cá nhân (Customer)
  • Mục tiêu học thuật: Vận dụng kiến thức Java Swing, SQLite, thiết kế giao diện Desktop, kiến trúc 3 lớp, kiểm thử tự động JUnit 5.

CHƯƠNG 2: CÔNG NGHỆ VÀ CÔNG CỤ SỬ DỤNG

2.1. Ngôn ngữ lập trình

  • Java (Java SE / Java Swing): Sử dụng phiên bản Java 25 (maven.compiler.source=25, maven.compiler.target=25).
  • Java Swing: Thư viện GUI mạnh mẽ cho ứng dụng Desktop, kết hợp với FlatLaf Look and Feel tạo giao diện hiện đại.

2.2. Cơ sở dữ liệu

  • SQLite (Libris.db): Cơ sở dữ liệu nhẹ, không cần server, lưu trữ dạng file.
  • Cấu trúc gồm 5 bảng chính: Users, Customers, Books, RentalOrders, RentalOrderDetails.
  • Sử dụng WAL mode (Write-Ahead Logging) để tăng hiệu suất đọc/ghi.
  • Dữ liệu mẫu: 33 sách, 13 khách hàng, 3 tài khoản, 8 đơn thuê.

Hình 3.1: Sơ đồ chức năng hệ thống Libris

Phân quyền Admin (Quản trị viên)

  • Quản lý sách: Thêm, sửa, xóa, tìm kiếm, lọc sách.

Phân quyền Customer (Khách hàng)

  • Xem thư viện: Tìm kiếm, lọc sách có sẵn (BooksView — chế độ xem).

  • Trả sách: Trả sách cho đơn có trạng thái Renting.
  • Hồ sơ cá nhân: Xem/cập nhật thông tin, đổi mật khẩu.

4.2. Hiện thực kết nối cơ sở dữ liệu

Lớp DatabaseConnection.java (package utils):

  • Sử dụng phương thức static getConnection() để tạo kết nối mới mỗi lần gọi.
  • Kết nối đến file Libris.db qua URL: jdbc:sqlite:Libris.db
  • Cấu hình tối ưu: WAL mode, synchronous=NORMAL, foreign_keys=ON, busy_timeout=30000ms.
  • Tự động khởi tạo database từ script database.sql nếu bảng chưa tồn tại (synchronized initialization).
public static Connection getConnection() throws SQLException {
    Class.forName("org.sqlite.JDBC");
    Properties props = new Properties();
    props.setProperty("journal_mode", "WAL");
    props.setProperty("synchronous", "NORMAL");
    props.setProperty("foreign_keys", "ON");
    props.setProperty("busy_timeout", "30000");
    
    Connection conn = DriverManager.getConnection(Constants.URL, props);
    // PRAGMA statements for SQLite optimization
    stmt.execute("PRAGMA journal_mode=WAL;");
    stmt.execute("PRAGMA synchronous=NORMAL;");
    stmt.execute("PRAGMA foreign_keys=ON;");
    
    // Auto-initialize database if tables don't exist
    synchronized (INITIALIZATION_LOCK) {
        if (!isInitialized) {
            initializeDatabase(conn);
            isInitialized = true;
        }
    }
    return conn;
}

  • DashboardView: Hiển thị thống kê tổng quan: tổng sách, sách có sẵn, sách đang thuê, tổng khách hàng, tổng đơn thuê. Sử dụng JFreeChart cho biểu đồ.
  • ReportsView: Báo cáo chi tiết: doanh thu hàng tháng, sách phổ biến, thống kê thể loại, top khách hàng, sách quá hạn. Xuất Excel qua Apache POI.

5.4. Đánh giá ưu nhược điểm của ứng dụng

Ưu điểm

  • Giao diện thân thiện, hiện đại (FlatLaf): Giao diện đẹp, phẳng, dễ sử dụng, hỗ trợ icon SVG thông qua FlatLaf-Extras.
  • Kiến trúc 3 lớp rõ ràng: Tách biệt UI / Controller / DAO, dễ dàng bảo trì và mở rộng.
  • Phân quyền rõ ràng: Admin và Customer có chức năng riêng biệt, menu Sidebar thay đổi theo role.
  • Tính năng tài chính: Hỗ trợ tính toán giá thuê, tiền cọc, phí trễ hạn — cấu trúc tốt cho quản lý tài chính thư viện.
  • Báo cáo phong phú: Dashboard tổng quan, đa dạng loại thống kê (doanh thu, sách phổ biến, thể loại, quá hạn), xuất Excel.
  • Kiểm thử tự động: JUnit 5 + Page Object Model, 9 test case đạt 100%.
  • Auto-initialize Database: Tự động tạo bảng và dữ liệu mẫu khi chạy lần đầu từ script database.sql.
  • Cấu hình SQLite tối ưu: WAL mode, busy_timeout, foreign keys — đảm bảo tính toàn vẹn dữ liệu.

Nhược điểm

  • Ứng dụng chạy dạng Desktop: Chưa triển khai Web/Cloud, hạn chế truy cập từ xa.
  • Cơ sở dữ liệu SQLite: Không hỗ trợ đồng thời nhiều người dùng, giới hạn về quy mô.
  • Mật khẩu chưa mã hóa: Password lưu plaintext trong DB (nên hash bằng BCrypt).
  • Chưa có tính năng thanh toán trực tuyến.
  • Test coverage còn hạn chế: Chưa có test cho CRUD sách, tạo đơn thuê, duyệt/từ chối đơn.

5.5. Hướng phát triển trong tương lai

  • Chuyển đổi lên Web/Cloud: Xây dựng ứng dụng web bằng Java Spring Boot, RESTful API.
  • Nâng cấp cơ sở dữ liệu: Chuyển từ SQLite sang MySQL hoặc PostgreSQL cho đa người dùng.
  • Mã hóa mật khẩu: Sử dụng BCrypt hoặc Argon2 để hash password.
  • Tích hợp thanh toán trực tuyến: Thêm chức năng thanh toán online (VNPay, Momo).
  • Tính năng đa ngôn ngữ: Hỗ trợ tiếng Anh và các ngôn ngữ khác (i18n).
  • Thông báo tự động: Gửi email/SMS nhắc nhở trả sách khi gần hạn.
  • Mở rộng test coverage: Thêm test cho các luồng CRUD, tạo đơn, duyệt đơn, trả sách.
